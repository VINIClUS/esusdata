# Discovery — e-SUS PEC CT 133 (2026-09-19)

Read-only inspection of the authorized e-SUS PEC installation on Proxmox CT 133. Every query in
this document ran with `default_transaction_read_only=on` and a `statement_timeout`. **Nothing in
the PEC was modified** — no INSERT/UPDATE/DELETE/DDL, no `pg_hba.conf` edit, no role/grant created.

### CT 133 access change made (minimal, reversible)

CT 133 had **no `authorized_keys` file for any user** and `root`'s password is locked
(`passwd -S root` → `L`) — password login is therefore impossible; key-based login is the only
path. A dedicated ed25519 keypair (`~/.ssh/observatorio-pec`, comment
`observatorio-aps-pec-tunnel`) was generated on the workstation and its **public** key appended to
`/root/.ssh/authorized_keys` on CT 133. No other file, service, or configuration on CT 133 was
touched.

**Revert:** `pct exec 133 -- sed -i '/observatorio-aps-pec-tunnel/d' /root/.ssh/authorized_keys`
(matches on the key comment; removes exactly the one appended line).

## Verified against pgJDBC (not just psql)

A spike (`pgjdbc-spike`, not part of the shipped codebase) connected through the SSH tunnel with
`org.postgresql:postgresql:42.7.13`, applied the same five session controls, ran the frozen adapter
query with `TYPE_FORWARD_ONLY` / `fetchSize=1000` / autocommit off, and reproduced the psql baseline
exactly: `TOTAL=10029 PROGRAMADOS=7100 ESPONTANEOS=2929 FORA=0 PCT=70.7947`, computed via
`BigInteger`/`BigDecimal` (no `double`). This resolves the one previously-unverified link in the
dependency matrix.

One binding note for the adapter: pgJDBC infers parameter types from the bound Java type. Binding a
date-range predicate with `setString` sends the parameter as `varchar` and PostgreSQL 9.6 rejects
`date >= character varying` with no implicit cast. The adapter must bind date parameters with
`java.sql.Date` / `setObject(..., Types.DATE)`, never as strings.
